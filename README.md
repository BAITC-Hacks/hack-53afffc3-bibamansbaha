# hack-53afffc3-bibamansbaha
Hackathon team repository for BibaMansBaha

## EKT Assistant

ИИ-ассистент для подбора электротехнических товаров: запрос, спецификация или фото → сопоставление с каталогом → проверяемое предложение → явное подтверждение → сохранённая корзина.

Реализовано на Next.js/React/TypeScript. Живой каталог ekt.kz и OpenAI проверены реальными запросами. **Корзина — серверный прототип на SQLite**: API корзины магазина не предоставлен, заказы и оплаты не выполняются. Аналоги с совпадающими критическими параметрами проверены на отдельно маркированном синтетическом каталоге; live-данных для безопасной замены пока недостаточно.

### Запуск

Нужен Node.js 24+ и npm. Установка с lockfile:

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev
```

Открыть [приложение](http://127.0.0.1:3000), [корзину](http://127.0.0.1:3000/cart), [пример виджета](http://127.0.0.1:3000/embed). По умолчанию `.env.example` выбирает `fixture`, который не требует ключей. Если `.env.local` уже существует, сохранить его; не выполнять копирование поверх файла с доступами.

Для реального каталога: `CATALOG_MODE=live`, `EKT_API_USERNAME`, `EKT_API_PASSWORD`. Для текстовой модели и фото: `OPENAI_API_KEY`, `OPENAI_MODEL` (проверен `gpt-4.1-mini`). Ключи только в `.env.local` или серверном окружении, без `NEXT_PUBLIC_`. После изменения конфигурации перезапустить сервер. `APP_ORIGIN` должен совпадать с точным origin браузера, включая порт; по умолчанию `http://127.0.0.1:3000`.

```powershell
npm run build
npm start
```

Production-конфигурация использует Secure-cookie: для полноценной production-сессии нужен HTTPS. Нужен Node-сервер с постоянным writable-диском; статический export и эфемерный serverless-диск не подходят для SQLite. Развёртывание не выполнялось.

### Возможности и границы

- Поиск по артикулу/ID и тексту, карточки с источником, временем, ценой, остатком и предупреждениями.
- Реальное извлечение XLSX, DOCX, текстового PDF, JPEG/PNG/WebP; сканы PDF распознаются моделью. Дополнительно CSV/TXT. Старые XLS/DOC нужно пересохранить в современные форматы.
- До 8 МБ, 100 позиций, 20 страниц PDF и 3 страниц скана для vision. Защита от архивных бомб, макросов и XML entities; формулы не исполняются. Тайм-бюджет 45 секунд для асинхронной обработки; синхронный Office-парсинг не изолирован в отдельный worker.
- Редактируемые строки, выбор кандидата, сохранение исходных единиц. Несовпадение единиц требует ручной проверки; автоматического пересчёта упаковок нет.
- Предложение действует 10 минут. Цена, остаток и техническая идентичность перепроверяются перед подтверждением. Изменение требует нового просмотра и подтверждения; неизвестные цена/остаток блокируют добавление.
- Атомарное сохранение и повторное подтверждение без дублирования. Корзина учитывает уже добавленное количество, поддерживает дробные метры в fixture, изменение количества и удаление.
- Оплата/доставка — ответы с официальными источниками. Несогласованные пороги бесплатной доставки показаны как противоречие. Сертификаты в проверенном API не обнаружены.
- Desktop/mobile и same-origin iframe. Cross-origin cookies, CMS магазина и production-аутентификация не интегрированы.

Режимы: `live` — текущие запросы к партнёрскому каталогу; `fixture` — явно синтетические данные; `snapshot` зарезервирован и отклоняется, пока нет проверенного снимка. Автоматической подмены live на fixture нет. Поиск по умолчанию ограничен двумя страницами / 40 товарами; это не полный каталог.

### Устройство проекта

- `src/server/catalog.ts` — ограниченный read-only адаптер, нормализация, поиск, консервативная проверка кандидатов.
- `src/server/attachments.ts`, `model.ts` — извлечение данных и OpenAI Responses со структурированной схемой. Модель не управляет корзиной и не назначает цены.
- `src/server/cart.ts` — SQLite, сессии, предложения, атомарное подтверждение и повторные запросы.
- `src/app/api/[action]/route.ts`, `src/server/http.ts` — схема запросов, CSRF/origin, лимиты, API приложения.
- `src/components` — чат, карточки, проверка строк, предложение, корзина и виджет.

Загрузки обрабатываются в памяти и не сохраняются. Диалог, сессия, извлечённые строки, предложения и корзина находятся в локальной SQLite (`DATABASE_PATH`); сессия истекает через 24 часа, её записи очищаются при создании следующей сессии. Исходные документы с доступами, `.env`, база и временные файлы исключены из Git. Не загружать платёжные реквизиты: распознаваемый платёжный текст блокируется перед сохранением и текстовым вызовом модели, старые сообщения маскируются при чтении. Это не универсальный детектор секретов; изображение до OCR не проверяется на содержимое.

Выбор и исключение строк сохраняются после обновления страницы. Исходные единицы не теряются; изменение количества или товара сбрасывает согласование упаковки. Предложение показывает стоимость корзины до/после и переоценку уже добавленного количества. Повторный confirm не дублирует запись; конфликт требует обновлённого предложения. Корзина поддерживает явное сохранение дробного количества и повторную проверку единиц.

Историческую очистку проверяйте отдельно: `node --import tsx scripts/clean-payment-messages.ts <путь-к-SQLite> --dry-run` выводит только счётчики. `--apply` заменяет найденные тела сообщений нейтральным текстом после отдельного решения владельца; стирание WAL, резервных копий и внешних журналов этим не гарантируется. Актуальный отчёт исправлений: [REPAIR_REPORT](docs/REPAIR_REPORT.md); исходный аудит сохранён без изменений.

### Git checkpoints

Разрешённый remote — этот репозиторий, ветка `main`. Явный выбор файлов, `git diff --cached --check` и `node scripts/check-secrets.mjs` перед commit; после push сравнить локальный SHA с `git ls-remote origin refs/heads/main`. Напоминатель `scripts/push-reminder.mjs` только сообщает сроки, никогда не делает commit/push. Во время разработки цель — 15 минут, подготовка на 12-й минуте; реальное время последней проверенной отправки хранится внутри `.git`.
